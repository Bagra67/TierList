# Architecture

English | [Français](architecture.fr.md)

How the TierList code is organized, and where new code goes. The engineering rules themselves are in [AGENTS.md](../AGENTS.md); this page describes how they apply to this repository today.

## Overview

```
Browser
  │
  ▼
React component ──► useX() hook ──► getX() ──► apiClient ──► /api/...   (frontend, Vite)
                    TanStack Query              openapi-fetch       │
                                                                    │ Vite proxy (dev): /api/x → :8000/x
                                                                    ▼
FastAPI route ──► service ──► repository ──► SQLAlchemy session ──► PostgreSQL   (backend)
 (HTTP only)     (business)   (queries)       (app/db/session.py)     (Docker)
```

The backend and the frontend only talk through HTTP. The contract between them is the OpenAPI schema: `backend/openapi.json`, generated from the FastAPI routes and Pydantic models, from which the frontend generates its TypeScript types.

## Frontend (`frontend/src/`)

| Layer         | Where                                    | Responsibility                                                                                                                         |
| ------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Components    | `App.tsx`, later `components/`, `pages/` | Display and user interaction only. Read server data through a hook; never call `fetch` or `useEffect` to load data.                    |
| Hooks         | `api/<resource>.ts` (`useHello`)         | One TanStack Query hook per read (`useQuery`) or write (`useMutation`); `queryKey` names the cached data.                              |
| API functions | `api/<resource>.ts` (`getHello`)         | One function per endpoint, through `apiClient`; throw `ApiError` on failure.                                                           |
| HTTP client   | `api/client.ts`                          | `apiClient` (openapi-fetch, base URL `/api`, typed by `schema.d.ts`) and `ApiError` (`status`, `body`, backend `detail` as `message`). |
| Query client  | `api/queryClient.ts`                     | Retry policy and logging of failed queries, in one place.                                                                              |
| API types     | `api/schema.d.ts`                        | Generated by `pnpm gen:api`; never edited by hand.                                                                                     |

Details and the template for a new endpoint: [frontend README, Data fetching](../frontend/README.md#8-data-fetching).

## Backend (`backend/app/`)

| Layer          | Where today                                                                       | Responsibility                                                                                                          |
| -------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Routes         | `main.py`                                                                         | HTTP only: parse the request, call a service, map expected errors to `HTTPException`, return a Pydantic response model. |
| Schemas        | `main.py` (`HelloResponse`, `HealthResponse`), `core/errors.py` (`ErrorResponse`) | Explicit request and response contracts (Pydantic). Never return ORM models directly.                                   |
| Services       | none yet                                                                          | Business rules and orchestration; own the transaction boundaries.                                                       |
| Repositories   | none yet                                                                          | Database queries (SQLAlchemy), no business rules.                                                                       |
| Models         | `db/base.py` (`Base`)                                                             | ORM models; their metadata is the target of Alembic migrations.                                                         |
| Infrastructure | `core/config.py`, `core/logging.py`, `core/errors.py`, `db/session.py`            | Settings from `.env`, logging, error format, engine and session (`get_db_session` dependency).                          |

### Target structure

The application has no business resource yet, so `main.py` still holds the few routes and schemas. With the **first real resource**, it will be split following AGENTS.md §10:

```
backend/app/
├── api/routes/<resource>.py   # routes (APIRouter), included by main.py
├── schemas/<resource>.py      # Pydantic request / response models
├── services/<resource>.py     # business logic
├── repositories/<resource>.py # database access
├── models/<resource>.py       # SQLAlchemy models (subclasses of db.base.Base)
├── core/                      # unchanged: config, logging, errors
├── db/                        # unchanged: Base, engine, session
└── main.py                    # app creation, error handlers, routers
```

Each new model comes with an Alembic migration (`uv run alembic revision --autogenerate -m "description"`), reviewed before commit.

## Cross-cutting conventions

- **API contract**: after changing a route or a schema, run `uv run python scripts/export_openapi.py` (backend) then `pnpm gen:api` (frontend), and commit both files. A test and a CI step check that they are up to date.
- **Errors**: every error response is an `ErrorResponse` (`{"detail": ..., "errors"?: [...]}`). Raise `HTTPException` for expected errors; unexpected exceptions become a generic, logged 500. See [backend README, Error format](../backend/README.md#12-error-format).
- **Health probes**: `GET /health` (liveness, no dependency) and `GET /health/db` (database reachable).
- **Configuration**: environment variables, read from `backend/.env` by pydantic-settings (`core/config.py`); `backend/.env.example` documents them. No secret in the code (gitleaks checks every commit).
- **Logging**: `logging.getLogger(__name__)` in `app/...`, level from `LOG_LEVEL`.
- **Tests**: backend in `backend/tests/` (unit, plus `integration/` against a real PostgreSQL), frontend next to the code (`*.test.tsx`). Every test is described in the [testing guide](testing.md).
- **Git**: Conventional Commits (checked by commitlint), one branch and one squash-merged PR per change into `develop`; see AGENTS.md §39–40.
