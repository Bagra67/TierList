# Translations (i18n)

English | [Français](i18n.fr.md)

The interface is available in **French** and **English**. French is the reference language. The rules are in [AGENTS.md §50](../AGENTS.md#50-internationalization-i18n); this page explains how it works and how to add a text, an error code or a language.

## How it works

| Piece             | Where                                               | Role                                                                                                                                                                             |
| ----------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Translations      | `frontend/src/i18n/locales/fr.ts`, `en.ts`          | One object per language, grouped by domain: `common`, `auth`, `account`, `errors`. `fr.ts` defines the keys; `en.ts` is typed `Translation` and must have exactly the same keys. |
| Setup             | `frontend/src/i18n/index.ts`                        | Initializes `i18next` + `react-i18next` with the bundled translations, detects the language, exposes `changeLanguage()`. Imported by `main.tsx` before the first render.         |
| Typed keys        | `frontend/src/i18n/i18next.d.ts`                    | `t('auth.login.title')` is checked by `pnpm typecheck`: a wrong key is a compile error.                                                                                          |
| Languages         | `frontend/src/constants/i18n.ts`                    | `SUPPORTED_LANGUAGES`, `DEFAULT_LANGUAGE` (`fr`), `LANGUAGE_STORAGE_KEY`, `LANGUAGE_NAMES`.                                                                                      |
| Language switcher | `frontend/src/components/LanguageSwitcher.tsx`      | Labelled `<select>` in the header of every page (`components/Layout.tsx`).                                                                                                       |
| API errors        | `frontend/src/errors/apiError.ts`, `googleError.ts` | Turn the error codes sent by the backend into translated messages.                                                                                                               |

### Choosing the language

On the first visit, the interface uses the first browser language that is supported (`en-US` → `en`), otherwise French. Choosing a language with the switcher applies it immediately and stores it in `localStorage`; it then wins over the browser language. If `localStorage` is unavailable (private browsing, blocked storage), the choice simply is not remembered. `<html lang>` always follows the interface language.

### Errors from the API

The backend never sends text meant for the user, except emails, written in French and English by the backend itself ([emails guide](emails.md)). Each error carries a stable **code** and, when needed, **params** ([backend README, Error format](../backend/README.md#12-error-format)):

```json
{
  "detail": "Invalid request",
  "code": "validation_error",
  "errors": [
    {
      "field": "body.password",
      "message": "…",
      "code": "password_too_short",
      "params": { "min_length": 8 }
    }
  ]
}
```

| Function                             | Input                                                                               | Message                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `translateError(t, error)`           | `ApiError` with a known `code`                                                      | `errors.api.<code>`, interpolated with `params`                              |
|                                      | `ApiError` with an unknown `code`                                                   | `errors.unknown`                                                             |
|                                      | Network error, or a response that is not an `ErrorResponse` (proxy without backend) | `common.backendUnreachable`                                                  |
| `translateFieldError(t, fieldError)` | Field error (422) with a known `code`                                               | `errors.field.<code>`, interpolated with `params` (e.g. `{{min_length}}`)    |
|                                      | Pydantic error type without a dedicated text                                        | `errors.field.invalid`                                                       |
| `translateGoogleError(t, code)`      | `?error=<code>` after Google sign-in                                                | `errors.google.<code>`, or `errors.google.google_failed` for an unknown code |

`detail` (English) and the Pydantic `message` are never displayed: they are for developers and logs.

## Recipes

### Add a text

1. Add the key to `fr.ts`, in the right domain (e.g. `auth.login.forgotPassword`).
2. Add the same key to `en.ts` (and to any other locale): `pnpm typecheck` fails until every locale has it.
3. In the component: `const { t } = useTranslation();` then `t('auth.login.forgotPassword')`. For a value, use interpolation: `'Signed in as {{name}}'` and `t('auth.signedInAs', { name })`.

### Add an error code

1. Backend: add the member to `ErrorCode` (`app/constants/error_codes.py`), an English `detail` to `app/constants/messages.py`, and raise `AppHTTPException(status_code, code=ErrorCode.X, detail=messages.X, params=...)`.
2. Regenerate the contract: `uv run python scripts/export_openapi.py` (backend), then `pnpm gen:api` (frontend).
3. Frontend: add `errors.api.<code>` to every locale (`errors.field.<code>` for a field error), using `{{param}}` for each param.
4. Document the code in the [backend README](../backend/README.md#12-error-format) and test it on both sides.

### Add a language

1. Add its code to `SUPPORTED_LANGUAGES` and its name to `LANGUAGE_NAMES` (`frontend/src/constants/i18n.ts`).
2. Create `frontend/src/i18n/locales/<code>.ts`, typed `Translation`, with every key translated.
3. Register it in `resources` in `frontend/src/i18n/index.ts`.
4. Add it to the tests of `i18n.test.ts` (same keys as French).

## Tests

Tests run in French: `src/test/setup.ts` switches to French before each test and forgets the stored choice after it. A test that checks another language calls `await i18n.changeLanguage('en')` first. The [testing guide](testing.md) describes each test.
