# Traductions (i18n)

[English](i18n.md) | Français

L'interface existe en **français** et en **anglais**. Le français est la langue de référence. Les règles sont dans [AGENTS.md §50](../AGENTS.md#50-internationalization-i18n) ; cette page explique le fonctionnement et comment ajouter un texte, un code d'erreur ou une langue.

## Fonctionnement

| Élément             | Où                                                  | Rôle                                                                                                                                                                               |
| ------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Traductions         | `frontend/src/i18n/locales/fr.ts`, `en.ts`          | Un objet par langue, rangé par domaine : `common`, `auth`, `account`, `errors`. `fr.ts` définit les clés ; `en.ts` est typé `Translation` et doit avoir exactement les mêmes clés. |
| Mise en place       | `frontend/src/i18n/index.ts`                        | Initialise `i18next` + `react-i18next` avec les traductions incluses dans le bundle, détecte la langue, expose `changeLanguage()`. Importé par `main.tsx` avant le premier rendu.  |
| Clés typées         | `frontend/src/i18n/i18next.d.ts`                    | `t('auth.login.title')` est vérifié par `pnpm typecheck` : une clé fausse est une erreur de compilation.                                                                           |
| Langues             | `frontend/src/constants/i18n.ts`                    | `SUPPORTED_LANGUAGES`, `DEFAULT_LANGUAGE` (`fr`), `LANGUAGE_STORAGE_KEY`, `LANGUAGE_NAMES`.                                                                                        |
| Sélecteur de langue | `frontend/src/components/LanguageSwitcher.tsx`      | `<select>` étiqueté dans l'en-tête de chaque page (`components/Layout.tsx`).                                                                                                       |
| Erreurs de l'API    | `frontend/src/errors/apiError.ts`, `googleError.ts` | Transforment les codes d'erreur envoyés par le backend en messages traduits.                                                                                                       |

### Choix de la langue

À la première visite, l'interface prend la première langue du navigateur qui est gérée (`en-US` → `en`), sinon le français. Choisir une langue avec le sélecteur l'applique aussitôt et la mémorise dans `localStorage` ; elle l'emporte ensuite sur la langue du navigateur. Si `localStorage` est indisponible (navigation privée, stockage bloqué), le choix n'est simplement pas mémorisé. `<html lang>` suit toujours la langue de l'interface.

### Erreurs de l'API

Le backend n'envoie jamais de texte destiné à l'utilisateur, sauf les emails, qu'il rédige lui-même en français et en anglais ([guide des emails](emails.fr.md)). Chaque erreur porte un **code** stable et, si besoin, des **params** ([README backend, Format d'erreur](../backend/README.fr.md#12-format-derreur)) :

```json
{
  "detail": "Invalid request",
  "code": "validation_error",
  "errors": [
    {
      "field": "body.password",
      "message": "…",
      "code": "password_too_short",
      "params": { "min_length": 8 }
    }
  ]
}
```

| Fonction                             | Entrée                                                                           | Message                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `translateError(t, error)`           | `ApiError` avec un `code` connu                                                  | `errors.api.<code>`, avec les `params` interpolés                             |
|                                      | `ApiError` avec un `code` inconnu                                                | `errors.unknown`                                                              |
|                                      | Erreur réseau, ou réponse qui n'est pas une `ErrorResponse` (proxy sans backend) | `common.backendUnreachable`                                                   |
| `translateFieldError(t, fieldError)` | Erreur de champ (422) avec un `code` connu                                       | `errors.field.<code>`, avec les `params` interpolés (ex. `{{min_length}}`)    |
|                                      | Type d'erreur Pydantic sans texte dédié                                          | `errors.field.invalid`                                                        |
| `translateGoogleError(t, code)`      | `?error=<code>` au retour de Google                                              | `errors.google.<code>`, ou `errors.google.google_failed` pour un code inconnu |

`detail` (en anglais) et le `message` de Pydantic ne sont jamais affichés : ils servent aux développeurs et aux logs.

## Recettes

### Ajouter un texte

1. Ajouter la clé dans `fr.ts`, dans le bon domaine (ex. `auth.login.forgotPassword`).
2. Ajouter la même clé dans `en.ts` (et dans toute autre langue) : `pnpm typecheck` échoue tant qu'une langue ne l'a pas.
3. Dans le composant : `const { t } = useTranslation();` puis `t('auth.login.forgotPassword')`. Pour une valeur, utiliser l'interpolation : `'Connecté en tant que {{name}}'` et `t('auth.signedInAs', { name })`.

### Ajouter un code d'erreur

1. Backend : ajouter le membre à `ErrorCode` (`app/constants/error_codes.py`), un `detail` en anglais dans `app/constants/messages.py`, et lever `AppHTTPException(status_code, code=ErrorCode.X, detail=messages.X, params=...)`.
2. Régénérer le contrat : `uv run python scripts/export_openapi.py` (backend), puis `pnpm gen:api` (frontend).
3. Frontend : ajouter `errors.api.<code>` dans chaque langue (`errors.field.<code>` pour une erreur de champ), avec `{{param}}` pour chaque param.
4. Documenter le code dans le [README backend](../backend/README.fr.md#12-format-derreur) et le tester des deux côtés.

### Ajouter une langue

1. Ajouter son code à `SUPPORTED_LANGUAGES` et son nom à `LANGUAGE_NAMES` (`frontend/src/constants/i18n.ts`).
2. Créer `frontend/src/i18n/locales/<code>.ts`, typé `Translation`, avec toutes les clés traduites.
3. L'enregistrer dans `resources` dans `frontend/src/i18n/index.ts`.
4. L'ajouter aux tests de `i18n.test.ts` (mêmes clés que le français).

## Tests

Les tests tournent en français : `src/test/setup.ts` repasse en français avant chaque test et oublie le choix mémorisé après. Un test qui vérifie une autre langue appelle d'abord `await i18n.changeLanguage('en')`. Le [guide des tests](testing.fr.md) décrit chaque test.
