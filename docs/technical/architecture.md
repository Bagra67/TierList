# Architecture

English | [Français](architecture.fr.md)

How the TierList code is organized, and where new code goes. The engineering rules themselves are in [AGENTS.md](../../AGENTS.md); this page describes how they apply to this repository today.

## Overview

```
Browser
  │
  ▼
React component ──► useX() hook ──► getX() ──► apiClient ──► /api/...   (frontend, Vite)
                    TanStack Query              openapi-fetch       │
                                                                    │ Vite proxy (dev): /api/x → :8000/x
                                                                    ▼
FastAPI route ──► service ──► repository ──► SQLAlchemy session ──► PostgreSQL   (backend)
 (HTTP only)     (business)   (queries)       (app/db/session.py)     (Docker)
```

The backend and the frontend only talk through HTTP. The contract between them is the OpenAPI schema: `backend/openapi.json`, generated from the FastAPI routes and Pydantic models, from which the frontend generates its TypeScript types.

## Frontend (`frontend/src/`)

| Layer         | Where                                                                                  | Responsibility                                                                                                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components    | `App.tsx` (routes, react-router), `pages/`, `components/`, `auth/`                     | Display and user interaction only. Read server data through a hook; never call `fetch` or `useEffect` to load data.                                                                                                                                                                                |
| Hooks         | `api/<resource>.ts` (`useCurrentUser`)                                                 | One TanStack Query hook per read (`useQuery`) or write (`useMutation`); `queryKey` names the cached data.                                                                                                                                                                                          |
| API functions | `api/<resource>.ts` (`getMe`)                                                          | One function per endpoint, through `apiClient`; throw `ApiError` on failure (`dataOrThrow`, `throwIfError`).                                                                                                                                                                                       |
| HTTP client   | `api/client.ts`                                                                        | `apiClient` (openapi-fetch, base URL `/api`, typed by `schema.d.ts`), in-memory access token and refresh middleware.                                                                                                                                                                               |
| Errors        | `errors/apiError.ts`, `errors/googleError.ts`                                          | `ApiError` (`status`, `body`, `code`, `params`, backend `detail` as `message`), `getFieldErrors` (422 errors per field), and `translateError` / `translateFieldError` / `translateGoogleError` (error code → translated message).                                                                  |
| UI components | `components/ui/` (shadcn/ui), `index.css`                                              | Generic components generated by shadcn/ui (Radix primitives, Tailwind CSS v4 classes): owned by the project and editable. Business components stay in `components/`. Theme (colors, radius, font) in `index.css`. See [frontend README, UI components](../../frontend/README.md#10-ui-components). |
| Translations  | `i18n/` (`locales/fr.ts`, `locales/en.ts`), `components/LanguageSwitcher.tsx`          | Every displayed text goes through `t()` (react-i18next); French is the reference, English must have the same keys. See the [i18n guide](i18n.md).                                                                                                                                                  |
| Theme         | `theme/`, `constants/theme.ts`, `components/ThemeSwitcher.tsx`, script in `index.html` | Light / dark / system preference stored in the browser; the `dark` class on `<html>` switches the colors of `index.css`. See [frontend README, Dark mode](../../frontend/README.md#dark-mode).                                                                                                     |
| Constants     | `constants/`                                                                           | Fixed values: routes, HTTP statuses, auth limits and paths, supported languages, themes. No literal in components or API functions; displayed texts are translations, not constants.                                                                                                               |
| Query client  | `api/queryClient.ts`                                                                   | Retry policy and logging of failed queries, in one place.                                                                                                                                                                                                                                          |
| API types     | `api/schema.d.ts`                                                                      | Generated by `pnpm gen:api`; never edited by hand.                                                                                                                                                                                                                                                 |

Details and the template for a new endpoint: [frontend README, Data fetching](../../frontend/README.md#8-data-fetching).

## Backend (`backend/app/`)

| Layer          | Where today                                                                                                       | Responsibility                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes         | `api/routes/auth.py`, `main.py` (health)                                                                          | HTTP only: parse the request, call a service, map expected errors to `AppHTTPException` (with an `ErrorCode`), return a Pydantic response model.                        |
| Schemas        | `schemas/auth.py`, `main.py` (`HealthResponse`), `core/errors.py` (`ErrorResponse`)                               | Explicit request and response contracts (Pydantic). Never return ORM models directly.                                                                                   |
| Services       | `services/auth.py`, `services/email.py`                                                                           | Business rules and orchestration; own the transaction boundaries.                                                                                                       |
| Repositories   | `repositories/users.py`, `repositories/refresh_tokens.py`                                                         | Database queries (SQLAlchemy), no business rules.                                                                                                                       |
| Models         | `db/base.py` (`Base`), `models/user.py`                                                                           | ORM models; their metadata is the target of Alembic migrations.                                                                                                         |
| Infrastructure | `core/config.py`, `core/logging.py`, `core/errors.py`, `core/security.py`, `db/session.py`, `api/dependencies.py` | Settings from `.env`, logging, error format, password and token primitives, engine and session (`get_db_session` dependency), shared dependencies (`get_current_user`). |
| Constants      | `constants/` (`auth.py`, `google.py`, `error_codes.py`, `messages.py`, `logging.py`)                              | Fixed values: cookie names, token types, lengths tied to the schema, Google URLs, API error codes, developer-facing API messages.                                       |
| Exceptions     | `exceptions/` (`auth.py`, `google.py`, `http.py`)                                                                 | Domain exceptions, raised by services and mapped to HTTP responses by routes; `AppHTTPException`, the HTTP error carrying an `ErrorCode`.                               |

### Structure

Since the first real resource (authentication), the backend follows AGENTS.md §10; `main.py` still holds the health routes:

```
backend/app/
├── api/routes/<resource>.py   # routes (APIRouter), included by main.py
├── schemas/<resource>.py      # Pydantic request / response models
├── services/<resource>.py     # business logic
├── repositories/<resource>.py # database access
├── models/<resource>.py       # SQLAlchemy models (subclasses of db.base.Base)
├── constants/                 # fixed values (names, limits, URLs, API messages)
├── exceptions/                # domain exceptions
├── core/                      # config, logging, errors, security
├── db/                        # unchanged: Base, engine, session
└── main.py                    # app creation, error handlers, routers
```

Each new model comes with an Alembic migration (`uv run alembic revision --autogenerate -m "description"`), reviewed before commit.

## Cross-cutting conventions

- **API contract**: after changing a route or a schema, run `uv run python scripts/export_openapi.py` (backend) then `pnpm gen:api` (frontend), and commit both files. A test and a CI step check that they are up to date.
- **Errors**: every error response is an `ErrorResponse` (`{"detail": ..., "code": ..., "params"?: {...}, "errors"?: [...]}`). `code` is a stable error code that the frontend translates; `detail` is English text for developers. Raise `AppHTTPException` with an `ErrorCode` for expected errors; unexpected exceptions become a generic, logged 500. See [backend README, Error format](../../backend/README.md#12-error-format).
- **Health probes**: `GET /health` (liveness, no dependency) and `GET /health/db` (database reachable).
- **Authentication**: a protected route depends on `get_current_user` (`api/dependencies.py`), which checks the Bearer access token. Flows, tokens and code map: [authentication guide](authentication.md).
- **Configuration**: environment variables, read from `backend/.env` by pydantic-settings (`core/config.py`); `backend/.env.example` documents them. No secret in the code (gitleaks checks every commit).
- **Constants and settings**: no magic number or hard-coded message in routes, services or components.
  - A value that may need to change per environment (delay, timeout, validation rule such as `PASSWORD_MIN_LENGTH`) is a **setting**: a field of `Settings` with a default, documented in `backend/.env.example` and the backend README. It can then be changed without a pull request.
  - A fixed value (cookie name, algorithm, Google URL, length tied to a database column) is a **constant** in `constants/` (backend `app/constants/`, frontend `src/constants/`).
  - Alembic migrations keep literal values: a migration is a snapshot of the schema and must not follow a constant that changes later.
- **Translations**: no user-facing text hard-coded in a component, and none sent by the backend: the API returns error codes, the frontend translates them. Every key exists in French and English. Rules: AGENTS.md §50; how-to: [i18n guide](i18n.md).
- **Exceptions**: domain exceptions live in `app/exceptions/` (backend) and error classes in `src/errors/` (frontend), never inside services, routes or components.
- **Logging**: `logging.getLogger(__name__)` in `app/...`, level from `LOG_LEVEL`.
- **Tests**: backend in `backend/tests/` (unit, plus `integration/` against a real PostgreSQL), frontend next to the code (`*.test.tsx`). Every test is described in the [testing guide](testing.md).
- **Git**: Conventional Commits (checked by commitlint), one branch and one squash-merged PR per change into `develop`; see AGENTS.md §39–40.
