# Templates

How templates are stored and exposed by the API: data model, endpoints, soft deletion and purge, snapshots taken when a game starts, moderation, visibility, official templates, and where it lives in the code. What a template is for the user: [product](../product/product.md).

## 1. Functional overview

A template is what gets ranked: its **tiers** (the rows of the tier list) and its **tiles** (the items to rank). It is **private** to its owner, until the owner makes it **public** (§2.8): everyone can then open its page (§2.10).

| Action                          | Endpoint                                 | Result                                                                                                      |
| ------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Create a template               | `POST /templates`                        | A template with the six default tiers (S to E) and no tile.                                                 |
| List my templates               | `GET /templates`                         | My active templates, with their number of tiles, the most recently modified first.                          |
| See what the moderation deleted | `GET /templates/removed`                 | My templates deleted by the moderation and not purged yet, with the date and the reason.                    |
| Open a template                 | `GET /templates/{id}`                    | The template, its tiers and its tiles, sorted by position.                                                  |
| Rename a template               | `PATCH /templates/{id}`                  | The new name; the last modification date is updated.                                                        |
| Make it public or private       | `PUT /templates/{id}/visibility`         | The chosen visibility; the date of the first publication is kept (§2.8).                                    |
| Open a public template          | `GET /marketplace/templates/{id}`        | Without an account: name, owner, tags, tiers and tiles; `404` when it is not public any more (§2.10).       |
| Add a tier                      | `POST /templates/{id}/tiers`             | A tier at the bottom, named `?`, color `#9AA0B4`.                                                           |
| Change a tier                   | `PATCH /templates/{id}/tiers/{tier_id}`  | Its name, its color and/or its position (the others are shifted).                                           |
| Delete a tier                   | `DELETE /templates/{id}/tiers/{tier_id}` | The tier disappears, the others move up; refused for the last tier.                                         |
| Add a tile                      | `POST /templates/{id}/tiles`             | A tile with a text, an image or both, at the end; refused beyond the maximum number of tiles.               |
| Change a tile                   | `PATCH /templates/{id}/tiles/{tile_id}`  | Its text, its image (replace or remove) and/or its position in the template order.                          |
| Delete a tile                   | `DELETE /templates/{id}/tiles/{tile_id}` | The tile disappears, the next ones move up.                                                                 |
| Delete a template               | `DELETE /templates/{id}`                 | The template disappears for its owner at once, and is erased permanently after the retention period (§2.3). |

On the frontend, the _My templates_ page lists, creates and deletes templates; the editor renames the template, chooses its visibility and configures its tiers and its tiles (a text, an image or both). See §3.

### Rules

- **Name**: 1 to 100 characters, surrounding spaces removed (a name made only of spaces is empty, hence refused with a `422`).
- **Default tiers**, from top to bottom: `S` `#FF3B6B`, `A` `#FF8A2A`, `B` `#FFC22E`, `C` `#7BD94A`, `D` `#2EC4B6`, `E` `#5B7CFA` (`DEFAULT_TIERS`, `app/constants/templates.py`). Ink text (`#1D1640`) keeps a 4.5:1 contrast on each of them. Changing these values only affects new templates: the colors are data of each template.
- **Tiers**: name 1 to 50 characters (spaces removed), color `#RRGGBB` stored in upper case. A template keeps **at least one tier**: deleting the last one answers `409` `last_tier`.
- **Positions** of tiers start at 0 and stay continuous (no gap): moving or deleting a tier renumbers the others. A position past the end puts the tier last.
- **Empty update**: a `PATCH` without any field (or with only `null` values) changes nothing, not even the last modification date; the tier must still exist (`404` otherwise).
- The same goes for the tiles: an empty `PATCH` of a tile changes nothing.
- **Tiles**: a **text, an image, or both**, never neither (`422` `tile_empty`). The text has 1 to 200 characters (spaces removed); a text made only of spaces is a `422` `validation_error`, `null` means "no text". The image is one uploaded before by the owner (`POST /images`, see the [images guide](images.md)); an unknown image or one of another user is a `404` `image_not_found`. In a `PATCH`, an explicit `null` **removes** the text or the image, as long as the tile keeps the other one; `position: null` is ignored. The tiles follow the same position rules as the tiers: their order is the **template order**.
- **Tile limit** (free plan): **32 tiles** per template (`FREE_PLAN_MAX_TILES`), **256** for an official template (`OFFICIAL_TEMPLATE_MAX_TILES`, §2.11), returned as `max_tiles` in `TemplateResponse` (property `Template.max_tiles`, which will depend on the owner's plan). Beyond it, `409` `tile_limit_reached` with the param `max_tiles`.
- **Simultaneous changes**: every change of the tiers or tiles locks the template row (`SELECT … FOR UPDATE`) until its commit. Two requests on the same template run one after the other, the second one seeing the result of the first: two simultaneous deletions cannot remove the last tier, two simultaneous additions cannot go beyond the tile limit.
- **Last modification** (`updated_at`): changes when the template changes, and must also change when one of its tiers or tiles changes: the service updates it explicitly (§2.2). It is the date shown to the user and the order of the list.
- **Privacy**: a template of another user answers `404`, exactly like an unknown or deleted one: the API never reveals that it exists.
- **Account deletion** erases the user's templates, deleted ones included. The snapshots of the games played with them stay (§2.4).
- **Moderation**: a super admin can hide, unhide or delete a template, with a reason (#268), and restore or erase a deleted one (§2.3). A hidden template stays its owner's, who still reads and edits it and sees the reason, but no new room nor new game can start with it (`409` `template_hidden`); games in progress finish. Details: §2.7.
- **Visibility**: the owner makes a template public or private. Making it public needs a confirmed email, a template not hidden by the moderation and at least one tile; the date of the first publication is kept. Details: §2.8.
- **Tags**: at most 5 per template (20 for an official template), 30 characters each, in the owner's order; a tag equal to an earlier one ignoring case and accents is dropped, and a tag needs at least one Latin letter or digit (`422` `invalid_tag`). Details: §2.9.
- **Official templates** (#492): owned by the site's account « TierList », edited by the super admins one at a time under an edit lease, published and featured from the moderation area. Details: §2.11.

## 2. Technical design

### 2.1 Data model

```
users ──< templates ──< tiers
              │
              ├──────< tiles
              │
              └──────< template_tags
```

| Table           | Columns                                                                                                                                                                                                                                                                             | Notes                                                                                                                                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `templates`     | `id`, `owner_id` → `users`, `name` (100), `created_at`, `updated_at`, `deleted_at`, `moderation`, `moderation_reason` (500), `deletion_reason` (500), `visibility`, `first_made_public_at`, `search_text`, `featured_at`, `editing_by_id` → `users`, `editing_until`, `edit_logged` | `ON DELETE CASCADE` towards `users`; index on `owner_id`. `moderation` and `moderation_reason`: §2.7; `visibility` and `first_made_public_at`: §2.8; `search_text` and its GIN index: §2.9; `featured_at`, `editing_by_id` (`ON DELETE SET NULL`), `editing_until` and `edit_logged`: §2.11, used by the official templates only. |
| `tiers`         | `id`, `template_id` → `templates`, `name` (50), `color` (`#RRGGBB`), `position`, dates                                                                                                                                                                                              | `ON DELETE CASCADE` towards `templates`; `position` 0 = top.                                                                                                                                                                                                                                                                      |
| `tiles`         | `id`, `template_id` → `templates`, `text` (200, empty for an image-only tile), `image_id` → `images` (empty for a text-only tile), `position`, dates                                                                                                                                | `ON DELETE CASCADE` towards `templates`; no `ON DELETE` towards `images` (only the garbage collection erases an image); `position` 0 = first.                                                                                                                                                                                     |
| `template_tags` | `template_id` → `templates`, `normalized_label`, `label` (30), `position`                                                                                                                                                                                                           | Primary key `(template_id, normalized_label)`; index on `normalized_label`; `ON DELETE CASCADE` towards `templates`; §2.9.                                                                                                                                                                                                        |

`position` has **no unique constraint**: reordering would break it while the other rows are being shifted. The service keeps positions continuous.

### 2.2 Model mixins

The common columns are shared through SQLAlchemy mixins (`app/db/mixins.py`). Each model takes only the ones it needs:

| Mixin                 | Columns                    | Used by                                                |
| --------------------- | -------------------------- | ------------------------------------------------------ |
| `UUIDPrimaryKeyMixin` | `id` (UUID v4)             | `Template`, `Tier`, `Tile`, the snapshot tables (§2.4) |
| `TimestampMixin`      | `created_at`, `updated_at` | `Template`, `Tier`, `Tile`                             |
| `SoftDeleteMixin`     | `deleted_at` (nullable)    | `Template`                                             |

- The dates are set by PostgreSQL with `clock_timestamp()`, not `now()`: `now()` is the start of the transaction, the same for every write of one transaction.
- `onupdate` only sees an `UPDATE` of the row itself: when a tier or a tile changes, the service must update the template's `updated_at` explicitly.
- `SoftDeleteMixin` is not put everywhere on purpose: a soft-deleted table forces every query to filter `deleted_at`.

### 2.3 Soft deletion and purge

`DELETE /templates/{id}` only sets `deleted_at`. Every query of the repository filters `deleted_at IS NULL`, so the template disappears at once for its owner (`404`, absent from the list).

The command `scripts/purge_deleted_templates.py` then erases permanently the templates deleted more than `DELETED_TEMPLATE_RETENTION_DAYS` days ago; their tiers and tiles go with them (`ON DELETE CASCADE`), while the snapshots taken from them stay (§2.4). It logs and prints the number of templates purged, and can be run again safely: it only removes what has expired.

```bash
# in backend/
uv run python scripts/purge_deleted_templates.py
```

It runs every night in the app process, with the other purges ([deployment guide](deployment.md#23-nightly-tasks), #192); the command above runs it by hand.

Until then, super admins see the deleted templates and can restore them or erase them earlier ([moderation guide](moderation.md#212-deleted-templates), #104).

### 2.4 Snapshots (template versions)

Decided and built in #82. A game is played on a **snapshot**: a frozen copy of the template's tiers and tiles, taken when the game starts ([domain model](../product/milestone-1/domain-model.md), US-1.6, US-1.7, US-3.1).

| Topic          | Options                                                                                     | Choice and reason                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Storage        | Version the template rows; JSON copy in one column; **relational copy in dedicated tables** | **Relational copy**: the rounds and placements of a game will reference the snapshot tiles through foreign keys, and the image foreign key keeps the garbage collection right. The template stays simple. |
| Images         | Duplicate the files; **reference the same image**                                           | **Same image**: an image is immutable, so the snapshot always shows the one it was taken with; the garbage collection keeps the images a snapshot uses ([images guide](images.md)).                       |
| Link to source | `CASCADE`; **`SET NULL`**                                                                   | **`SET NULL`**: the purge of a deleted template and the deletion of the account keep the games played with it.                                                                                            |
| Transaction    | The snapshot commits on its own; **the caller commits it with the game**                    | **Caller**: the game start creates the snapshot and the game in one transaction, so no snapshot is left without its game.                                                                                 |

| Table                | Columns                                                                                     | Notes                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `template_snapshots` | `id`, `template_id` → `templates` (nullable), `name` (100), `taken_at`                      | `ON DELETE SET NULL` towards `templates`; `taken_at` set with `clock_timestamp()`. No `updated_at`: frozen. |
| `snapshot_tiers`     | `id`, `snapshot_id` → `template_snapshots`, `name` (50), `color`, `position`                | `ON DELETE CASCADE` towards the snapshot.                                                                   |
| `snapshot_tiles`     | `id`, `snapshot_id` → `template_snapshots`, `text` (200), `image_id` → `images`, `position` | `ON DELETE CASCADE` towards the snapshot; no `ON DELETE` towards `images`, like `tiles.image_id`.           |

Rules (`TemplateService.take_snapshot(user, template_id)`):

- It copies the name, the tiers and the tiles with their positions. Editing, deleting or purging the template afterwards never changes the snapshot; the next game takes a new one, with the current version.
- It reads a **playable** template (`get_playable_template`): one of the user, or a public template of another account under the listing rule (§2.10, #273). A **deleted** template, a private one of another user, or one of another user that is no longer listed (private again, hidden, deleted, owner banned) raises `TemplateNotFoundError` (`template_not_found`): no new game can start with it, and the reason is not given. A game already started keeps its snapshot and can finish.
- A template **hidden by the moderation** raises `TemplateHiddenError` (`template_hidden`, §2.7): no new game can start with it.
- A template **without tiles** raises `TemplateHasNoTilesError` (`template_has_no_tiles`): a game would have no item to rank.
- It takes a **shared** lock on the template row (`for_share`, `SELECT … FOR SHARE`): an edit by the owner, which takes `FOR UPDATE`, waits for the copy, but rooms that start a game on the same public template at the same time do not wait for each other. It only **flushes**: the caller commits the snapshot together with the game, and the lock holds until then.
- The game start calls it (`GameService.start`, [games guide](games.md)).

### 2.6 Endpoints

Every route requires the Bearer access token (`401` otherwise), except the public template page (§2.10).

| Method and path                          | Body                            | Success                             | Errors                     |
| ---------------------------------------- | ------------------------------- | ----------------------------------- | -------------------------- |
| `POST /templates`                        | `{name}`                        | `201` `TemplateResponse`            | `401`, `422`               |
| `GET /templates?cursor=`                 | —                               | `200` `TemplateListResponse`        | `400`, `401`               |
| `GET /templates/removed`                 | —                               | `200` `RemovedTemplateListResponse` | `401`                      |
| `GET /templates/{id}`                    | —                               | `200` `TemplateResponse`            | `401`, `404`               |
| `PATCH /templates/{id}`                  | `{name}`                        | `200` `TemplateResponse`            | `401`, `404`, `409`, `422` |
| `PUT /templates/{id}/tags`               | `{tags}`                        | `200` `TemplateResponse`            | `401`, `404`, `409`, `422` |
| `POST /templates/{id}/tiers`             | —                               | `201` `TemplateResponse`            | `401`, `404`, `409`        |
| `PATCH /templates/{id}/tiers/{tier_id}`  | `{name?, color?, position?}`    | `200` `TemplateResponse`            | `401`, `404`, `409`, `422` |
| `DELETE /templates/{id}/tiers/{tier_id}` | —                               | `200` `TemplateResponse`            | `401`, `404`, `409`        |
| `POST /templates/{id}/tiles`             | `{text?, image_id?}`            | `201` `TemplateResponse`            | `401`, `404`, `409`, `422` |
| `PATCH /templates/{id}/tiles/{tile_id}`  | `{text?, image_id?, position?}` | `200` `TemplateResponse`            | `401`, `404`, `409`, `422` |
| `DELETE /templates/{id}/tiles/{tile_id}` | —                               | `200` `TemplateResponse`            | `401`, `404`, `409`        |
| `DELETE /templates/{id}`                 | —                               | `204`                               | `401`, `404`               |

- `TemplateResponse` is `{id, name, tags, created_at, updated_at, tiers: [{id, name, color, position}], tiles: [{id, text, image_url, image_removed, image_status, image_moderation_reason, position}], max_tiles, max_tags, moderation, moderation_reason, visibility, first_made_public_at, official, featured, editing_by_name, editing_until}`, tiers and tiles sorted by `position`; `moderation` and `moderation_reason` are described in §2.7, the official fields in §2.11. `image_url` is the public address of the compressed image, `null` for a text-only tile; `template_response` (`api/presenters/templates.py`) builds it with `optional_image_url` (`api/presenters/images.py`), like every image of the API.
- `TemplateListResponse` is `{items: [{id, name, tags, tile_count, updated_at, moderation, moderation_reason, removed_images}], next_cursor}`: a page of 24 templates (`TEMPLATES_PAGE_SIZE`), most recently modified first (`updated_at DESC, id DESC`), and the cursor of the next page, `null` on the last one (#105, [marketplace guide](marketplace.md#27-pagination)). `TemplateService.page_for_owner` reads 25 rows for a page of 24, and the tags and removed images of that page only; a cursor that cannot be read answers `400` `invalid_cursor`. The moderation page of an account keeps the whole list (`list_for_owner`). _My templates_ reads the pages with an infinite query (`useTemplates`, same key, so the invalidations reload the pages already read) and "Voir plus"; the home page takes its three templates from the first page. An object rather than an array, so that pagination could add a field without breaking the contract. The list reads the templates and counts their tiles in **one query**, then the tags of all the templates in one more (§2.9): never one query per template (no N+1).
- Every change route also answers `409` `official_template_locked` for an official template whose edit lease the caller does not hold (§2.11).
- The tier and tile routes return the whole template, so that the editor replaces its copy without reading it again. The `404` is `template_not_found` for the template, `tier_not_found` / `tile_not_found` for a tier or a tile that is not in it.

### 2.7 Moderation

A super admin can **hide**, **unhide** or **delete** the template of any user, with a reason (US-1.5, #268). The routes, the moderation log and the reason are in the [moderation guide](moderation.md#22-writing-an-entry); this section describes what it changes for the template.

| Column              | Content                                                                                                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `moderation`        | `TemplateModeration` (`models/enums.py`): `none` or `hidden`. Text with the CHECK constraint `ck_templates_template_moderation` (`text_enum`), server default `none`. |
| `moderation_reason` | The reason of the hide, at most 500 characters, shown to the owner; `null` when the template is not hidden.                                                           |

- **Hide** (`TemplateModerationService.hide`): `moderation` becomes `hidden`, with the reason. **Unhide**: back to `none`, the reason is cleared. **Delete**: sets `deleted_at`, exactly like a deletion by the owner (§2.3), from a visible or a hidden template; the nightly purge erases it later, and the games already played keep their snapshot (§2.4).
- **Why the reason is copied on the template**: the moderation log is purged after 3 years, a template can stay hidden longer.
- **Conflicts**: hiding a hidden template, unhiding one that is not hidden, or any action on a deleted template answers `409` `template_moderation_conflict`. A purged or unknown template is a `404` `template_not_found`.
- **Locking**: the template row is locked (`SELECT … FOR UPDATE`, `get_template_for_update`), whatever its owner, deleted or not, until the action commits. The change and its log entry (target `template`, label the template name) are committed together.
- **Last modification unchanged**: the change goes through an `UPDATE` that keeps `updated_at`, since it is the owner's last change, not a moderation decision. The order of _My templates_ does not move.
- **What a hidden template blocks**: `RoomService.create` and `TemplateService.take_snapshot` (the game start) raise `TemplateHiddenError` for its owner, so `POST /rooms` and `POST /rooms/{code}/game` answer `409` `template_hidden`; another account gets `template_not_found`, without the reason (§2.10) ([rooms guide](rooms.md), [games guide](games.md)). A game already in progress finishes: it only depends on its snapshot.
- **What the owner keeps**: a hidden template is still read, listed and edited by its owner. `TemplateResponse` and the items of `TemplateListResponse` carry `moderation` and `moderation_reason`; the room of a hidden template says so with `template.hidden` in `RoomResponse` when the room admin is the owner, never in a room started on someone else's template ([rooms guide](rooms.md)). The [privacy policy](legal-pages.md) says that the owner sees the reason.
- **What the owner sees of a decision** (US-1.10, #270): `removed_images`, in the items of `TemplateListResponse`, gives for each tile with a removed image its id, text and position, the decision (`hidden` or `deleted`) and the reason; one extra query reads them for all the templates (`list_tiles_with_removed_image_of_owner`). `TileResponse` gives the same with `image_status` and `image_moderation_reason`. A template deleted by the moderation leaves `GET /templates`: `GET /templates/removed` lists it, with its name, the date and the reason, until its purge (§2.3). This route reads the moderation log (`list_templates_deleted_by_moderation`): a deletion by the owner has no entry, so it is not listed, and the retention of the log is much longer than the one of a deleted template. The name of the super admin is never exposed.
- **Frontend**: the editor shows a notice (`TemplateHiddenNotice`, `role="status"`) with the reason, saying that the template can still be edited but no game can start with it, and has no "Create a room" button; _My templates_ and the recent templates of the home page show a "Hidden" badge (`TemplateHiddenBadge`, a written status, not only a color) instead of that button; the lobby of a room whose template is hidden shows a message instead of the "Start the game" button.
- **Frontend of the decisions**: _My templates_ shows the reason of a hidden template and, on each row, the removed images (the tile, then `RemovedImageDecision`); the `RemovedTemplates` section lists the templates deleted by the moderation, without a link since they can no longer be opened, and shows nothing when there are none. The editor shows `RemovedImageDecision` under the image of a tile. The moderation dialogs warn the super admin that the owner will see the reason.
- **Separate from the owner's visibility**: moderation is its own column, apart from the visibility chosen by the owner (§2.8). Hiding a public template leaves it `public`, and unhiding it gives back the owner's choice. A hidden template cannot be made public, but can be made private.
- **Super admin screen**: the account page (#127, [moderation guide](moderation.md#28-accounts)) lists the templates of an account with these actions; the reports queue (#269) will call them too.

### 2.8 Visibility

The owner chooses whether a template is **private** or **public** (US-2.1, US-2.3, #271). The visibility and the moderation (§2.7) are two separate columns: a hidden template keeps the visibility its owner chose.

| Column                 | Content                                                                                                                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `visibility`           | `TemplateVisibility` (`models/enums.py`): `private` or `public`. Text with the CHECK constraint `ck_templates_template_visibility` (`text_enum`), server default `private`.                           |
| `first_made_public_at` | The date the template was made public **for the first time**, `null` until then. It never changes afterwards: going back to private, then public again, does not move a template up among the newest. |

- **Route**: `PUT /templates/{id}/visibility` with `{"visibility": "private" | "public"}` answers `TemplateResponse`. `TemplateResponse` and the items of `TemplateListResponse` carry `visibility` and `first_made_public_at`.
- **Making it public** (`TemplateService.set_visibility`) needs, in this order: a confirmed email (`403` `email_not_verified`), a template not hidden by the moderation (`409` `template_hidden`), at least one tile (`409` `template_has_no_tiles`). The template row is locked (`SELECT … FOR UPDATE`, like every change), so a hide at the same time cannot slip between the checks and the change.
- **Making it private** is always accepted, even on a hidden template. Sending the visibility the template already has changes nothing.
- **Only the owner**: another user's template, a deleted or an unknown one answers `404` `template_not_found` (§1).
- **Bans**: no check in the route, since a banned account can no longer call the API ([authentication guide](authentication.md#banned-accounts)). The marketplace will not list the templates of a banned owner (invariant 2 of the [domain model](../product/milestone-2/domain-model.md#invariants); listing rule in the [marketplace guide](marketplace.md#22-listing-rule)).
- **What it changes for now**: everyone can open the page of a public template (§2.10), and any signed-in user starts a room and its games with it (`get_playable_template`, §2.4, [rooms guide](rooms.md#rules)); only the owner edits it (`get_owned_template`). The marketplace (#277) will read this column too. When a template goes back to private, a game in progress finishes: it only depends on its snapshot (§2.4).
- **Last modification**: changing the visibility updates `updated_at`, like a rename.
- **Seed data**: some templates of the seed are public, one of them hidden ([seed data guide](seed-data.md)).
- **Frontend**: `TemplateVisibilityField`, next to the name in the editor (two columns on a large screen). It stays compact: on a 720 px high screen, larger cards and notice left room for less than two tiers.
  - A `fieldset` with two native radios on one line, `Privé` and `Public`, and one help line under them: the description of the checked choice. Each radio is described by its own description (`aria-describedby`); the one of the other choice stays for screen readers (`sr-only`). The checked radio has an ink border, not the buzzer pink: "Créer une salle" stays the main action of the area.
  - Saved on change through `useSetTemplateVisibility`, with an optimistic update undone on a refusal. The radios stay enabled while saving, so that the keyboard focus is kept.
  - When public, the help line ends with "Première publication le …" and, unless the template is hidden, a "Voir la page publique" link (§2.10).
  - `Public` is disabled, with the reason linked to it, for a template without tiles or a hidden one. A hidden public template says that it does not appear among the public templates.
  - An unconfirmed email shows a one-line notice with a small `ResendVerificationEmailButton`, but `Public` stays enabled: the current user is cached forever (`staleTime: Infinity`), so an email confirmed in another tab must not block the choice, and the backend decides. While the cached email is unconfirmed, `useCurrentUser({ refreshUntilEmailVerified: true })` reads the account again on mount and when the tab comes back, once its cached copy is more than 10 s old (`UNVERIFIED_ACCOUNT_STALE_MS`, a short `staleTime`), so the notice goes away once the email is confirmed elsewhere. The notice follows the cached account only: a `403` `email_not_verified` reads the account again, and so does a successful publication while the cache says unconfirmed.
  - _My templates_ shows a written "Public" badge (`TemplatePublicBadge`) next to "Create a room".

### 2.9 Tags

The owner gives a template up to 5 tags, so that people find it in the marketplace (US-2.2, #272). The storage was decided in spike #274 ([marketplace guide](marketplace.md#24-tags)).

| Column                           | Content                                                                                                                                                                                                                                                    |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `template_tags.label`            | The tag as typed, surrounding spaces removed, at most 30 characters (`TAG_MAX_LENGTH`). The one shown everywhere.                                                                                                                                          |
| `template_tags.normalized_label` | `normalize_search_text(label)` (`core/search_text.py`): ligatures `œ` and `æ` written out, accents dropped, `casefold`, every character other than `a-z0-9` turned into a space. `Text`, since the normalization can lengthen a label (`ß` gives `ss`).    |
| `template_tags.position`         | The owner's order, from 0.                                                                                                                                                                                                                                 |
| `templates.search_text`          | The normalized name followed by the normalized tags, `''` by default. The partial GIN index `ix_templates_listed_search` on `to_tsvector('simple', search_text)`, for the public, not hidden, not deleted templates, serves the marketplace search (#277). |

- **Route**: `PUT /templates/{id}/tags` with `{"tags": [...]}` **replaces the whole list** and answers `TemplateResponse`. Adding or removing one tag sends the new list: one route, idempotent, like the visibility.
- **Rules** (`SetTemplateTagsRequest`, then `TemplateService.set_tags`): 30 characters each, `422` `validation_error` on a tag (`tags.0`…); the schema refuses more than 20 tags (`OFFICIAL_TEMPLATE_MAX_TAGS`, `422` on `tags`). The service then applies the template's own limit, `Template.max_tags` (5, `TEMPLATE_MAX_TAGS`, or 20 for an official template), counted after the duplicates are dropped: `409` `tag_limit_reached` with the param `max_tags`. `TemplateResponse` carries `max_tags`. A tag equal to an earlier one after normalization is dropped and the first one kept (US-2.2). A tag whose normalized form is empty (only punctuation, or a non-Latin script) is refused with `422` `invalid_tag`, and the list does not change.
- **Kept tags**: a tag present before and after keeps its row (its label and position are updated), so the primary key never collides when the unit of work inserts before it deletes.
- **`search_text`** is written by `_refresh_search_text` on every path that changes the name or the tags: `create`, `rename` and `set_tags`. `rename` locks the row too, so that a rename and a tag change at the same time keep it consistent. The snapshot does not copy the tags: a game does not show them.
- **Last modification**: changing the tags updates `updated_at`.
- **Responses**: `TemplateResponse.tags`, and the `tags` of the items of `TemplateListResponse` (also on the super admin account page, which reuses them). The list reads the tags of all the owner's templates in **one extra query** (`list_tags_of_owner`), not one per template.
- **Seed data**: some themes have tags, one with a case duplicate that is merged ([seed data guide](seed-data.md)).
- **Frontend**: `TemplateTagsField`, under the name in the editor, in the space next to the visibility: a new row would shrink the scrolling tier and tile areas.
  - One field frame holds the tags as pills (`tagPillClassName`: `rounded-full`, neutral `secondary`, never a tier color nor the buzzer, [visual identity](visual-identity.md#5-shapes-shadow-and-motion)), then the text field. A counter `2 / 5` with tabular figures, like the tile counter, out of `max_tags`; at the limit, a sentence replaces the text field.
  - Enter or leaving the field adds the tag, Escape empties the draft, as for the name (`InlineEditField`). No optimistic update: merging duplicates is a backend rule, so the field shows the answer. The text stays while saving (read-only, with a spinner) and after an error. When the saved list did not grow, "Cette étiquette est déjà là." is announced (`aria-live`).
  - Each remove button is 24 px with the name "Retirer l'étiquette « … »". The buttons stay focusable while saving (`aria-disabled`) and ignore the click. After a removal, the focus goes to the next remove button, or to the text field.
  - _My templates_ shows the tags of each template as compact pills (`TemplateTagList`), without links: the tag filter comes with the marketplace (#277).

### 2.10 Public template page

Anyone, signed in or not, opens the page of a public template before playing it (US-3.3, #275).

- **Listing rule**: `listed_templates_condition(now)` (`repositories/templates.py`), decided in spike #274 ([marketplace guide](marketplace.md#22-listing-rule)): public, not hidden, not deleted, and the owner has no active ban at `now` (`is_active` of `repositories/account_bans.py`). A temporary ban that ends brings the page back without any job. `get_listed_template_with_owner_name` reads one template under this condition, with its tiers, tiles, tags and its owner's display name (one join, no second query); `get_listed_template_name_and_owner` reads only what a report stores.
- **Route**: `GET /marketplace/templates/{template_id}` (`api/routes/marketplace.py`), without authentication and without any user dependency, like the results page: an expired or invalid access token never prevents reading it (`get_optional_user` would answer `401`). `MarketplaceService.get_template` (`services/marketplace.py`) calls it.
- **Response** `PublicTemplateResponse` (`schemas/marketplace.py`, built by `api/presenters/marketplace.py`): `{id, name, owner_name, tags, tiers: [{id, name, color, position}], tiles: [{id, text, image_url, image_removed}]}`, in the owner's order. Nothing that only the owner sees: no visibility, moderation, reason, `max_tiles` or image status. `image_url` and `image_removed` come from `optional_image_url` and `is_image_removed`, like every image of the API.
- **Not available**: a template that is private, hidden, deleted, whose owner is banned, or unknown answers the same `404` `template_not_found`, so the page never says why (US-3.3), like `results_not_found` for the results.
- **Served page**: the backend writes the template's name, owner and first visible image into the page's title and link preview tags, and answers a real `404` when the template is not available ([search engines guide](seo.md#2-pages)). The listed templates are in `/sitemap.xml`.
- **Report**: `POST /reports` with `target_kind: "template"`, for a listed template only ([moderation guide](moderation.md#210-content-reports)).
- **Create a room** (US-2.4, #273): a signed-in user, the owner included, creates a room with the template from this page and becomes its room admin; the template stays read only for them ([rooms guide](rooms.md#rules)). A visitor is asked to sign in and comes back to the page afterwards, Google sign-in included (`return_to`, [authentication guide](authentication.md#google-sign-in-openid-connect)).
- **Likes** (US-3.4, #276): the page shows the number of likes (`like_count`). A signed-in user who may like it (`can_like`, and a confirmed email address, otherwise the button shows why) gets a toggle button "J'aime · 12" (`aria-pressed`, `components/LikeButton.tsx`); the owner sees the count only; a visitor gets "Se connecter pour aimer" and comes back after signing in ([marketplace guide](marketplace.md#210-likes)).
- **Back to the marketplace**: a "← Modèles publics" link, and the tags link to `/marketplace?tag=…` ([marketplace guide](marketplace.md#4-frontend)).
- **Not shown yet**: the lineage of a fork (#279), and the other actions (favorite #278, copy #279) come with their issues, on this page.
- **Frontend**: `PublicTemplatePage`, at `/marketplace/templates/:templateId` (`ROUTES.PUBLIC_TEMPLATE`, `publicTemplatePath`), outside `RequireAuth`.
  - The name (`h1`), "par …", the tags (`TemplateTagList`), the tiers as color chips (`TemplateTierChips`), then the items in a grid of 2 to 6 columns (`TemplateTileCard`: the image or the "image removed" visual, then the text); an empty state when no item is left. `ReportButton` sits next to the title, as on the results page.
  - `TemplateTierChips` and `TemplateTileCard` are shared with the moderation template page, which adds its "image hidden" note to the card.
  - A `404` `template_not_found`, or an address that is not a template id (no request is sent), shows `NotFoundPage` with the "Modèle indisponible" title and message, and its button back home; any other error shows the translated error.
  - `usePublicTemplate` (`api/marketplace.ts`), key `['marketplace', 'templates', id]`, not retried on a `4xx`.
  - The tab is named after the template (`useDocumentTitle`).
  - Next to `ReportButton`: `CreateRoomButton` for a signed-in user (`useCurrentUser`), as in _My templates_; for a visitor, a "Se connecter pour jouer" link to `/login` with the return state (`signInRedirectState`) and a hint; nothing while the session loads.

### 2.11 Official templates

The site publishes its own templates, signed « TierList » (#492). The super admins create and edit them in the moderation area ([moderation guide](moderation.md#213-official-templates)); the players play them like any public template and find the featured ones in the TierList picks ([marketplace guide](marketplace.md#211-tierlist-picks)).

- **Owner**: a system account, `OFFICIAL_ACCOUNT_ID` (`constants/templates.py`), display name `TierList`, address `official@tierlist.invalid`, inserted by the migration `7b2e4c9d1a03`. It has no password and no linked Google account, so nobody can sign in to it. It cannot be banned (`CannotBanSuperAdminError`) and the moderation account search leaves it out. `Template.is_official` is `owner_id == OFFICIAL_ACCOUNT_ID`: every query that joins the owner (marketplace, public page, search engines, deleted templates, reports) shows « par TierList » without a special case.
- **Draft or published**: the `visibility` column (§2.8). `private` is a draft, seen by the super admins only; `public` is published: listed under the usual rule (§2.10), playable and liked like any public template. A draft cannot be played, since it is neither the player's template nor listed. The owner's route `PUT /templates/{id}/visibility` answers `404` for an official template: the status changes go through the routes below.
- **Featured**: `featured_at`, the date it entered the TierList picks, `null` otherwise. Only a published template can be featured; unpublishing or deleting it clears the column.
- **Edit lease**: one super admin at a time edits an official template. `editing_by_id` and `editing_until` hold the lease, for `OFFICIAL_TEMPLATE_LOCK_SECONDS` (2 minutes). `POST …/lock` takes it, or renews it for its holder, and answers `409` `official_template_locked` with `params.editor` (a display name) while another super admin holds a lease that has not expired. The editor renews it every 30 s (`OFFICIAL_TEMPLATE_LOCK_RENEW_MS`) while its tab is visible, so a forgotten background tab frees the template within 2 minutes, and gives it back with `DELETE …/lock` a moment after it leaves the page (an editor mounted again in the meantime, e.g. by React strict mode, cancels the release so that it cannot reach the server after the new lock), or on `pagehide` (`keepalive`); a lease not given back expires on its own. A lock error other than `official_template_locked` is shown instead of the editor until a renewal succeeds. Taking over a lease held by someone else is not possible. Hiding or deleting a template through the moderation takes it out of the picks (`featured_at` cleared); the migration's downgrade deletes the official account and, through the cascade, every official template.
- **Content changes** go through the `/templates/{id}/…` routes (§2.6). `get_editable_template` (`repositories/templates.py`) gives a super admin the official templates as well as their own. `GET /templates/{id}` reads it without a lease; every change (`_get_for_change`) needs an active lease held by the caller, otherwise `409` `official_template_locked` (with `params.editor` when another super admin holds it). The owner-only routes (visibility, `DELETE /templates/{id}`) keep `get_owned_template`.
- **Log**: creating, publishing, unpublishing, featuring, unfeaturing and deleting write an entry to the moderation log, without a reason. The first content change committed in each lease writes one `edit` entry (a request that changes nothing writes none) (`edit_logged`, reset when a new lease starts after the previous one expired or was given back); creating counts as the first edit of its lease.
- **Limits**: 256 tiles (`OFFICIAL_TEMPLATE_MAX_TILES`) and 20 tags (`OFFICIAL_TEMPLATE_MAX_TAGS`), through `Template.max_tiles` and `Template.max_tags`; the players keep 32 and 5. The text lengths do not change. How a fork of an official template above the player limits behaves is decided in #279.
- **Locking**: every route below locks the template row (`SELECT … FOR UPDATE`; the bare row for `lock`, `unlock` and `delete`, the row with its content for the status changes), so two super admins never take the lease or change the status at the same time.
- **Deletion**: a soft delete (§2.3) that also clears the lease and `featured_at`. The template then appears in the deleted templates, where a super admin restores or erases it ([moderation guide](moderation.md#212-deleted-templates)).

| Method and path                                      | Body     | Success                               | Errors                     |
| ---------------------------------------------------- | -------- | ------------------------------------- | -------------------------- |
| `GET /moderation/official-templates`                 | —        | `200` `OfficialTemplateListResponse`  | `401`, `403`               |
| `POST /moderation/official-templates`                | `{name}` | `201` `TemplateResponse`              | `401`, `403`, `422`        |
| `POST /moderation/official-templates/{id}/lock`      | —        | `200` `OfficialTemplateLeaseResponse` | `401`, `403`, `404`, `409` |

- **List**: drafts and published templates, most recently changed first, each with its number of tiles, `visibility`, `featured` and the super admin holding its lease (`editing_by_name`).
- **Create**: a draft with the default tiers and no tile; the super admin who creates it holds its lease.
- **Status changes** are idempotent (publishing a published template changes nothing and writes no entry) and need the lease to be free or held by the caller (`409` `official_template_locked`). Publishing needs at least one tile (`409` `template_has_no_tiles`) and a template not hidden by the moderation (`409` `template_hidden`); featuring a draft answers `409` `template_not_published`, and featuring a template hidden by the moderation `409` `template_hidden`.
- **Response**: `TemplateResponse` carries `official`, `featured`, `editing_by_name` and `editing_until` (both `null` without an active lease), and `max_tiles` / `max_tags`.
- **Frontend**: `TemplateEditorPage` in official mode, at `/moderation/official-templates/:templateId` (`ROUTES.MODERATION_OFFICIAL_TEMPLATE`, `officialTemplateEditorPath`). `useOfficialTemplateLock` takes and renews the lease: a skeleton while it is pending; `OfficialTemplateReadOnly` while another super admin holds it (who is editing, the template read only, a new try at each renewal); with the lease, the usual editor, with `OfficialTemplateStatusField` (draft or published badge, publish, unpublish, feature, delete) in place of the visibility. A draft has no "Lancer une partie" button.

The template caches have separate keys (`constants/templates.ts`): `['templates', 'list']`, `['templates', 'removed']`, `['templates', 'detail', id]` and, for the public page, `['marketplace', 'templates', id]`. Creating a template puts it in the cache and reads the list again; deleting one removes it from the cache and reads the list and the removed list again. A change in the editor puts the returned template in the cache and reads the list again, but only when it is the last change pending for that template (`templateChangeMutationKey`, `isMutating`): an answer must not wipe the optimistic move of another change still pending, e.g. a tier and a tile moved at the same time. A failed change puts back the template it started from and reads it again. The editor treats an address that is not a template id (`isTemplateId`) as not found, without a request: `/templates/removed` would otherwise read the removed list. The template queries are not retried on a `4xx` (`retryUnlessClientError`).
