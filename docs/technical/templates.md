# Templates

English | [Français](templates.fr.md)

How templates are stored and exposed by the API: data model, endpoints, soft deletion and purge, snapshots taken when a game starts, moderation, and where it lives in the code. What a template is for the user: [product](../product/product.md).

## 1. Functional overview

A template is what gets ranked: its **tiers** (the rows of the tier list) and its **tiles** (the items to rank). It is **private** to its owner.

| Action            | Endpoint                                 | Result                                                                                                      |
| ----------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Create a template | `POST /templates`                        | A template with the six default tiers (S to E) and no tile.                                                 |
| List my templates | `GET /templates`                         | My active templates, with their number of tiles, the most recently modified first.                          |
| Open a template   | `GET /templates/{id}`                    | The template, its tiers and its tiles, sorted by position.                                                  |
| Rename a template | `PATCH /templates/{id}`                  | The new name; the last modification date is updated.                                                        |
| Add a tier        | `POST /templates/{id}/tiers`             | A tier at the bottom, named `?`, color `#9AA0B4`.                                                           |
| Change a tier     | `PATCH /templates/{id}/tiers/{tier_id}`  | Its name, its color and/or its position (the others are shifted).                                           |
| Delete a tier     | `DELETE /templates/{id}/tiers/{tier_id}` | The tier disappears, the others move up; refused for the last tier.                                         |
| Add a tile        | `POST /templates/{id}/tiles`             | A tile with a text, an image or both, at the end; refused beyond the maximum number of tiles.               |
| Change a tile     | `PATCH /templates/{id}/tiles/{tile_id}`  | Its text, its image (replace or remove) and/or its position in the template order.                          |
| Delete a tile     | `DELETE /templates/{id}/tiles/{tile_id}` | The tile disappears, the next ones move up.                                                                 |
| Delete a template | `DELETE /templates/{id}`                 | The template disappears for its owner at once, and is erased permanently after the retention period (§2.3). |

On the frontend, the _My templates_ page lists, creates and deletes templates; the editor renames the template and configures its tiers and its tiles (a text, an image or both). See §3.

### Rules

- **Name**: 1 to 100 characters, surrounding spaces removed (a name made only of spaces is empty, hence refused with a `422`).
- **Default tiers**, from top to bottom: `S` `#FF3B6B`, `A` `#FF8A2A`, `B` `#FFC22E`, `C` `#7BD94A`, `D` `#2EC4B6`, `E` `#5B7CFA` (`DEFAULT_TIERS`, `app/constants/templates.py`). Ink text (`#1D1640`) keeps a 4.5:1 contrast on each of them. Changing these values only affects new templates: the colors are data of each template.
- **Tiers**: name 1 to 50 characters (spaces removed), color `#RRGGBB` stored in upper case. A template keeps **at least one tier**: deleting the last one answers `409` `last_tier`.
- **Positions** of tiers start at 0 and stay continuous (no gap): moving or deleting a tier renumbers the others. A position past the end puts the tier last.
- **Empty update**: a `PATCH` without any field (or with only `null` values) changes nothing, not even the last modification date; the tier must still exist (`404` otherwise).
- The same goes for the tiles: an empty `PATCH` of a tile changes nothing.
- **Tiles**: a **text, an image, or both**, never neither (`422` `tile_empty`). The text has 1 to 200 characters (spaces removed); a text made only of spaces is a `422` `validation_error`, `null` means "no text". The image is one uploaded before by the owner (`POST /images`, see the [images guide](images.md)); an unknown image or one of another user is a `404` `image_not_found`. In a `PATCH`, an explicit `null` **removes** the text or the image, as long as the tile keeps the other one; `position: null` is ignored. The tiles follow the same position rules as the tiers: their order is the **template order**.
- **Tile limit** (free plan): **32 tiles** per template (`FREE_PLAN_MAX_TILES`), returned as `max_tiles` in `TemplateResponse` (property `Template.max_tiles`, which will depend on the owner's plan). Beyond it, `409` `tile_limit_reached` with the param `max_tiles`.
- **Simultaneous changes**: every change of the tiers or tiles locks the template row (`SELECT … FOR UPDATE`) until its commit. Two requests on the same template run one after the other, the second one seeing the result of the first: two simultaneous deletions cannot remove the last tier, two simultaneous additions cannot go beyond the tile limit.
- **Last modification** (`updated_at`): changes when the template changes, and must also change when one of its tiers or tiles changes: the service updates it explicitly (§2.2). It is the date shown to the user and the order of the list.
- **Privacy**: a template of another user answers `404`, exactly like an unknown or deleted one: the API never reveals that it exists.
- **Account deletion** erases the user's templates, deleted ones included. The snapshots of the games played with them stay (§2.4).
- **Moderation**: a super admin can hide, unhide or delete a template, with a reason (#268). A hidden template stays its owner's, who still reads and edits it and sees the reason, but no new room nor new game can start with it (`409` `template_hidden`); games in progress finish. Details: §2.7.

## 2. Technical design

### 2.1 Data model

```
users ──< templates ──< tiers
              │
              └──────< tiles
```

| Table       | Columns                                                                                                                                              | Notes                                                                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `templates` | `id`, `owner_id` → `users`, `name` (100), `created_at`, `updated_at`, `deleted_at`, `moderation`, `moderation_reason` (500)                          | `ON DELETE CASCADE` towards `users`; index on `owner_id`. `moderation` and `moderation_reason`: §2.7.                                         |
| `tiers`     | `id`, `template_id` → `templates`, `name` (50), `color` (`#RRGGBB`), `position`, dates                                                               | `ON DELETE CASCADE` towards `templates`; `position` 0 = top.                                                                                  |
| `tiles`     | `id`, `template_id` → `templates`, `text` (200, empty for an image-only tile), `image_id` → `images` (empty for a text-only tile), `position`, dates | `ON DELETE CASCADE` towards `templates`; no `ON DELETE` towards `images` (only the garbage collection erases an image); `position` 0 = first. |

`position` has **no unique constraint**: reordering would break it while the other rows are being shifted. The service keeps positions continuous.

### 2.2 Model mixins

The common columns are shared through SQLAlchemy mixins (`app/db/mixins.py`). Each model takes only the ones it needs:

| Mixin                 | Columns                    | Used by                                                |
| --------------------- | -------------------------- | ------------------------------------------------------ |
| `UUIDPrimaryKeyMixin` | `id` (UUID v4)             | `Template`, `Tier`, `Tile`, the snapshot tables (§2.4) |
| `TimestampMixin`      | `created_at`, `updated_at` | `Template`, `Tier`, `Tile`                             |
| `SoftDeleteMixin`     | `deleted_at` (nullable)    | `Template`                                             |

- The dates are set by PostgreSQL with `clock_timestamp()`, not `now()`: `now()` is the start of the transaction, the same for every write of one transaction.
- `onupdate` only sees an `UPDATE` of the row itself: when a tier or a tile changes, the service must update the template's `updated_at` explicitly.
- `SoftDeleteMixin` is not put everywhere on purpose: a soft-deleted table forces every query to filter `deleted_at`.

### 2.3 Soft deletion and purge

`DELETE /templates/{id}` only sets `deleted_at`. Every query of the repository filters `deleted_at IS NULL`, so the template disappears at once for its owner (`404`, absent from the list).

The command `scripts/purge_deleted_templates.py` then erases permanently the templates deleted more than `DELETED_TEMPLATE_RETENTION_DAYS` days ago; their tiers and tiles go with them (`ON DELETE CASCADE`), while the snapshots taken from them stay (§2.4). It logs and prints the number of templates purged, and can be run again safely: it only removes what has expired.

```bash
# in backend/
uv run python scripts/purge_deleted_templates.py
```

It runs every night in the app process, with the other purges ([deployment guide](deployment.md#23-nightly-tasks), #192); the command above runs it by hand.

### 2.4 Snapshots (template versions)

Decided and built in #82. A game is played on a **snapshot**: a frozen copy of the template's tiers and tiles, taken when the game starts ([domain model](../product/milestone-1/domain-model.md), US-1.6, US-1.7, US-3.1).

| Topic          | Options                                                                                     | Choice and reason                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Storage        | Version the template rows; JSON copy in one column; **relational copy in dedicated tables** | **Relational copy**: the rounds and placements of a game will reference the snapshot tiles through foreign keys, and the image foreign key keeps the garbage collection right. The template stays simple. |
| Images         | Duplicate the files; **reference the same image**                                           | **Same image**: an image is immutable, so the snapshot always shows the one it was taken with; the garbage collection keeps the images a snapshot uses ([images guide](images.md)).                       |
| Link to source | `CASCADE`; **`SET NULL`**                                                                   | **`SET NULL`**: the purge of a deleted template and the deletion of the account keep the games played with it.                                                                                            |
| Transaction    | The snapshot commits on its own; **the caller commits it with the game**                    | **Caller**: the game start creates the snapshot and the game in one transaction, so no snapshot is left without its game.                                                                                 |

| Table                | Columns                                                                                     | Notes                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `template_snapshots` | `id`, `template_id` → `templates` (nullable), `name` (100), `taken_at`                      | `ON DELETE SET NULL` towards `templates`; `taken_at` set with `clock_timestamp()`. No `updated_at`: frozen. |
| `snapshot_tiers`     | `id`, `snapshot_id` → `template_snapshots`, `name` (50), `color`, `position`                | `ON DELETE CASCADE` towards the snapshot.                                                                   |
| `snapshot_tiles`     | `id`, `snapshot_id` → `template_snapshots`, `text` (200), `image_id` → `images`, `position` | `ON DELETE CASCADE` towards the snapshot; no `ON DELETE` towards `images`, like `tiles.image_id`.           |

Rules (`TemplateService.take_snapshot(owner, template_id)`):

- It copies the name, the tiers and the tiles with their positions. Editing, deleting or purging the template afterwards never changes the snapshot; the next game takes a new one, with the current version.
- A **deleted** template, or one of another user, raises `TemplateNotFoundError` (`template_not_found`): no new game can start with it. A game already started keeps its snapshot and can finish.
- A template **hidden by the moderation** raises `TemplateHiddenError` (`template_hidden`, §2.7): no new game can start with it.
- A template **without tiles** raises `TemplateHasNoTilesError` (`template_has_no_tiles`): a game would have no item to rank.
- It locks the template like any change (`_get_for_change`) and only **flushes**: the caller commits the snapshot together with the game, and the lock holds until then.
- The game start calls it (`GameService.start`, [games guide](games.md)).

| Variable                          | Purpose                                                           | Default |
| --------------------------------- | ----------------------------------------------------------------- | ------- |
| `DELETED_TEMPLATE_RETENTION_DAYS` | Days a deleted template stays in the database before being purged | `30`    |

### 2.6 Endpoints

Every route requires the Bearer access token (`401` otherwise).

| Method and path                          | Body                            | Success                      | Errors                     |
| ---------------------------------------- | ------------------------------- | ---------------------------- | -------------------------- |
| `POST /templates`                        | `{name}`                        | `201` `TemplateResponse`     | `401`, `422`               |
| `GET /templates`                         | —                               | `200` `TemplateListResponse` | `401`                      |
| `GET /templates/{id}`                    | —                               | `200` `TemplateResponse`     | `401`, `404`               |
| `PATCH /templates/{id}`                  | `{name}`                        | `200` `TemplateResponse`     | `401`, `404`, `422`        |
| `POST /templates/{id}/tiers`             | —                               | `201` `TemplateResponse`     | `401`, `404`               |
| `PATCH /templates/{id}/tiers/{tier_id}`  | `{name?, color?, position?}`    | `200` `TemplateResponse`     | `401`, `404`, `422`        |
| `DELETE /templates/{id}/tiers/{tier_id}` | —                               | `200` `TemplateResponse`     | `401`, `404`, `409`        |
| `POST /templates/{id}/tiles`             | `{text?, image_id?}`            | `201` `TemplateResponse`     | `401`, `404`, `409`, `422` |
| `PATCH /templates/{id}/tiles/{tile_id}`  | `{text?, image_id?, position?}` | `200` `TemplateResponse`     | `401`, `404`, `422`        |
| `DELETE /templates/{id}/tiles/{tile_id}` | —                               | `200` `TemplateResponse`     | `401`, `404`               |
| `DELETE /templates/{id}`                 | —                               | `204`                        | `401`, `404`               |

- `TemplateResponse` is `{id, name, created_at, updated_at, tiers: [{id, name, color, position}], tiles: [{id, text, image_url, position}], max_tiles, moderation, moderation_reason}`, tiers and tiles sorted by `position`; `moderation` and `moderation_reason` are described in §2.7. `image_url` is the public address of the compressed image, `null` for a text-only tile; `template_response` (`api/presenters/templates.py`) builds it with `optional_image_url` (`api/presenters/images.py`), like every image of the API.
- `TemplateListResponse` is `{items: [{id, name, tile_count, updated_at, moderation, moderation_reason}]}`. An object rather than an array, so that pagination (#105) can add a field without breaking the contract. The list is read in **one query**: the database counts the tiles (no N+1).
- The tier and tile routes return the whole template, so that the editor replaces its copy without reading it again. The `404` is `template_not_found` for the template, `tier_not_found` / `tile_not_found` for a tier or a tile that is not in it.

### 2.7 Moderation

A super admin can **hide**, **unhide** or **delete** the template of any user, with a reason (US-1.5, #268). The routes, the moderation log and the reason are in the [moderation guide](moderation.md#22-writing-an-entry); this section describes what it changes for the template.

| Column              | Content                                                                                                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `moderation`        | `TemplateModeration` (`models/enums.py`): `none` or `hidden`. Text with the CHECK constraint `ck_templates_template_moderation` (`text_enum`), server default `none`. |
| `moderation_reason` | The reason of the hide, at most 500 characters, shown to the owner; `null` when the template is not hidden.                                                           |

- **Hide** (`TemplateModerationService.hide`): `moderation` becomes `hidden`, with the reason. **Unhide**: back to `none`, the reason is cleared. **Delete**: sets `deleted_at`, exactly like a deletion by the owner (§2.3), from a visible or a hidden template; the nightly purge erases it later, and the games already played keep their snapshot (§2.4).
- **Why the reason is copied on the template**: the moderation log is purged after 3 years, a template can stay hidden longer.
- **Conflicts**: hiding a hidden template, unhiding one that is not hidden, or any action on a deleted template answers `409` `template_moderation_conflict`. A purged or unknown template is a `404` `template_not_found`.
- **Locking**: the template row is locked (`SELECT … FOR UPDATE`, `get_template_for_update`), whatever its owner, deleted or not, until the action commits. The change and its log entry (target `template`, label the template name) are committed together.
- **Last modification unchanged**: the change goes through an `UPDATE` that keeps `updated_at`, since it is the owner's last change, not a moderation decision. The order of _My templates_ does not move.
- **What a hidden template blocks**: `RoomService.create` and `TemplateService.take_snapshot` (the game start) raise `TemplateHiddenError`, so `POST /rooms` and `POST /rooms/{code}/game` answer `409` `template_hidden` ([rooms guide](rooms.md), [games guide](games.md)). A game already in progress finishes: it only depends on its snapshot.
- **What the owner keeps**: a hidden template is still read, listed and edited by its owner. `TemplateResponse` and the items of `TemplateListResponse` carry `moderation` and `moderation_reason`; the room of a hidden template says so with `template.hidden` in `RoomResponse` ([rooms guide](rooms.md)). The [privacy policy](legal-pages.md) says that the owner sees the reason.
- **Frontend**: the editor shows a notice (`TemplateHiddenNotice`, `role="status"`) with the reason, saying that the template can still be edited but no game can start with it, and has no "Create a room" button; _My templates_ and the recent templates of the home page show a "Hidden" badge (`TemplateHiddenBadge`, a written status, not only a color) instead of that button; the lobby of a room whose template is hidden shows a message instead of the "Start the game" button.
- **Separate from the owner's visibility**: moderation is its own column, apart from the visibility the owner will choose (#271). Unhiding a template gives back the owner's choice.
- **Super admin screen**: the account page (#127, [moderation guide](moderation.md#28-accounts)) lists the templates of an account with these actions; the reports queue (#269) will call them too.

### 2.8 Known limitations

- No pagination of the list yet (#105).
- No super admin view of deleted templates yet (#104).
